Release notes 4.2

This release changes how projects are stored, how exports are named and how the command line reports progress. Read the migration section before you update a shared workspace, because older clients cannot open projects saved by this version.

Published 29 October 2026 by the platform team. Applies to the desktop app, the command line and the web editor.

Storage

Projects are now saved as a single bundle instead of a folder of loose files. Bundles open faster, sync more reliably and can be moved between machines without losing their history. Existing projects are converted the first time they are opened, and a backup of the original folder is kept next to the new bundle for thirty days.

Older clients cannot open converted projects. Update every machine that shares a workspace before anyone opens a project in version 4.2, or keep a copy of the folder until everyone has updated.

Exports

Export names now include the project name, the date and a short revision code, so files from different projects no longer overwrite each other in a shared downloads folder. The previous naming scheme is still available in the export settings for teams that depend on it.
